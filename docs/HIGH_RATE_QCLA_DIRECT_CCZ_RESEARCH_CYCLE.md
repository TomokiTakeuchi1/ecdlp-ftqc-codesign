## Research question

Can a high-rate-surgery logical architecture execute the parallel structure of a quantum carry-lookahead adder (QCLA) with lower realizable space-time cost than a memory-processor baseline, after exact PPM support, reaction time, resource-state supply, injection ports, routing, and logical failure are included?

The main arithmetic target remains a controlled modular-adder component of an ECDLP-256 Shor estimate. The first controlled experiment is a clean, out-of-place, modulo-\(2^n\) QCLA. It excludes modular reduction and in-place cleanup so that a loss of high-rate parallelism can be located before adding those mechanisms.

## Required direct-CCZ injection contract

Before a high-rate schedule is evaluated, a literature-backed contract must specify:

1. data-block support and resource-state support, including consumption, retention, and movement;
2. every logical PPM, its Pauli support, allowed weight, and geometry;
3. outcomes and the exact correction/frame update, distinguishing Pauli, Clifford, and non-Clifford corrections;
4. whether independent injections may share a preparation, measurement, routing, decoder, or correction resource;
5. the permitted high-rate family/batch size, duration, logical-error contribution, decoder throughput, and classical reaction latency;
6. ports, buffers, transport or surgery zones, and their occupancy; and
7. factory rate, burst capacity, storage error, and delivery latency.

The generic PBC lowering contract is not this contract: it lowers CCX into seven \(T\)-type consumptions. The direct-CCZ study must instead emit an event such as:

```text
CCZ_INJECT(data=(a,b,c), resource=ccz_state_k,
           ppm_supports=(...), outcomes=(...), correction_frame=(...),
           earliest_consume_time=..., reaction_dependencies=(...))
```

No seven-\(T\) lowering is part of this primary research stream.

## Research cycle

### 0. Pin the physical high-rate contract

Extract a machine-readable capability record from selected literature: native PPMs, family size, disjointness/overlap conditions, code parameters, operation time, error model, decoder throughput, classical-feedback latency, and I/O requirements. Record unsupported fields as `OPEN`; do not fill them with scaling extrapolations. This phase gates every runtime claim.

### 1. Produce a source-separated QCLA trace

Generate the clean OOP source DAG with named propagate/generate/prefix layers, data dependencies, and source CCX batch candidates. Validate arithmetic semantics and the Draper count/depth/workspace formulae. Record source critical path separately from scheduled depth.

### 2. Compile native direct-CCZ PPM events

Replace each source CCX by a direct-CCZ injection event plus explicit basis changes, state consumption, outcomes, and conditional correction frame. The compiler creates a reaction edge only when a later operation truly needs a resolved outcome. It rejects a backend capability record that lacks a required PPM or correction policy.

### 3. Schedule two reaction models on fully resident data

Initially exclude memory traffic so measurement and injection limits are identifiable. Schedule the same event trace under:

1. a conservative model with a classical-reaction barrier after every relevant injected-CCZ layer; and
2. an outcome/frame-tracked model that enforces only reaction frontiers proved necessary by the injection contract.

For each, report both the dependency lower bound and a resource-constrained schedule. Any improvement between models is numerical evidence only, not proof that the optimistic model is physical.

### 4. Add resource-state supply and buffer dynamics

Treat CCZ demand as a time series \(C(t)\), not an average. With delivery \(F(t)\) and buffer population \(B(t)\):

\[
B(t+1)=B(t)+F(t)-C(t), \qquad B(t)\ge 0.
\]

Report minimum initial buffer for no CCZ-supply stall, peak stored states, factory utilization, burst shortfall, delivery/routing contention, and storage-error contribution. Matching average demand is not evidence of a no-stall schedule.

### 5. Add processor, routing, and memory constraints

Introduce injection ports, measurement zones, decoder/classical throughput, and routing occupancy before moving data to memory. Then add memory load/store latency and bandwidth. Keep data residency, resource-state-bank capacity, and operation-zone capacity distinct. This stage turns source parallelism into an architecture-specific schedule.

### 6. Measure the in-place cleanup differential

Compile and schedule IP using the same physical contract. Its reversible reverse-prefix cleanup approximately doubles source CCX demand/depth at \(n=256\); it is not the Gidney temporary-AND pattern with controlled-CZ measurement uncompute. Compare CCZ demand, reaction frontiers, buffer pressure, routing, and failure budget rather than assuming cleanup is free or necessarily reactive.

### 7. Integrate controlled modular arithmetic

Only after the unmodular OOP/IP comparison has a validated backend contract, add controlled prime-modular reduction and the ECDLP calling context. Lookup, QROM, and other subroutines remain subsequent workload tracks, not hidden costs in this initial QCLA result.

- factory throughput, burst demand, buffer trajectory, and supply stalls;

- logical failure contributions from data, PPMs, resource states, storage, routing, decoding, and reaction delay; and
- an explicit lower-bound, heuristic-schedule, or realizable-upper-bound label.

## Ripple-carry comparison rule

Teleportation-based ripple carry remains the comparison workload. Its measurement-conditioned carry progression must use the same direct-CCZ contract where applicable, but its causal reaction chain must not be erased by naming a layer “parallel.” Conversely, QCLA source parallelism must not become runtime parallelism until the physical batch and correction contract admits it. The comparison is between realizable schedules under matched assumptions, not raw Toffoli count versus raw source depth.

## Exit criteria for the first cycle

The OOP direct-CCZ high-rate result is ready for cross-architecture comparison only when all of the following exist:

1. a pinned, reviewable direct-CCZ injection/high-rate capability record;
2. a validated OOP source trace and native event trace;
3. conservative and outcome/frame-tracked schedules with explicit reaction assumptions;
4. factory/buffer and port/routing models that explain every stall;
5. a decomposed failure budget; and
6. a reproducible result record and independent cross-review.

Until then, the claim that high-rate surgery plus OOP QCLA reaches the ECDLP target is `OPEN`.
