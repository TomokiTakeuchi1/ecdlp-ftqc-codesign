### F1. Hybrid semantics (tracked H both sides, bare CNOT, bare/frame X): reproduced with Stim

Stim 1.16 tableaus (tracked H = prepend only; bare CNOT = prepend+append;
bare X = prepend+append; frame/virtual X = prepend only) reproduced, for IP
width 256 and branches -2, -1, 0, 17, 63, 40 (6 branches x 2 X policies = 12
traces), every macro's PPMs (signed) and all 1,007 X and 1,007 Z images of
the retained final frame of the stored artifacts exactly. This independently
confirms the core claim that only the X-policy choice can affect signs, not
axes: from the stored data directly, all PPM and final-frame `(x,z)` pairs
are identical between `hybrid_bare` and `hybrid_frame` on every one of the 64
hashed branches (1,669-1,684 sign-only differences per branch on PPMs, but
**zero** PPM axis differences and, on this data, also zero final-frame sign
differences on every hashed branch — consistent with, though stronger than,
the contract's "signs...can differ").

I attempted an independent symbolic re-derivation of the abstract identity
`F_hybrid = G F_full` (G = physical bare-op prefix) using Stim tableau
composition and did not reach a conclusive confirmation: the exact
composition convention the codebase uses conflates two different column
updates (a basis-relabeling step shared by every tracked gate, and an
additional full re-conjugation of previously stored correction values that
only `apply_bare` performs on affected columns), and reproducing this from
scratch risked re-deriving the implementation rather than testing it
independently. I therefore verified this claim through its consequences
instead (below), which is sufficient to accept it as the explicitly-labeled
`PROVED (specification)` structural argument that it is.

### F2. Consequences of the frame identity: confirmed from data and from the grid

- **General-mode service is exactly branch-wise equal between hybrid and
  full tracking at every K, with unbounded W/S**, as the bilinear-form
  argument predicts (bare CNOT preserves the symplectic form, so the fixed
  regularizer produces the same generator groups and the same batch
  cardinalities when there is no weight/support cap to interact with the
  support values the two policies do differ on). Recomputed directly: the
  general-mode delta is **0 at all six K values on all 64 hashed branches**
  (384/384 comparisons), matching "not merely a coincidence of medians."
- **Real-Clifford even-Y invariant**: zero odd-Y PPMs found in the
  `hybrid_bare`, `hybrid_frame`, and `full` traces across all 64 hashed
  branches (checked directly from the stored signed PPM values, not only
  from the compiler's own guard).
- **QWC executed-weight equality between X policies**: confirmed — not
  separately re-stated in the contract table but implied by F1's axis
  equality.
