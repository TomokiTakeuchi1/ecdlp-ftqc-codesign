  upper bounds are 1,006/567. Since 4,462 profiles retain 118,501 unwitnessed

## Reviewer findings

This task refines the reviewed compatibility certificate (`RV-20260903-001`)
with per-PPM logical *support* (which named logical values a presented
observable actually touches), which is a new and independent mathematical
question from same-axis/commutation compatibility. The support-update algebra
(sparse Boolean-ANF propagation of `C†Z(q)C` through source CNOTs and the two
support-changing conditional corrections) is genuinely new math for this
review line, so verification prioritized checking it against ground truth
rather than re-deriving the tableau algebra by hand (a by-hand trace of the
two-step `_source_cnot_conjugate` update repeatedly produced results that
looked suspicious on paper; rather than trust an error-prone manual tableau
derivation, the review used the already-independently-verified compiler as
an oracle instead).

1. **Scope confirmation.** `git diff --stat` confirms this task adds one new
   module (`direct_ccz_ppm_support_certificate.py`) plus its replay, and
   touches only `scheduler/__init__.py` / `verification/__init__.py` with
   purely additive exports. No previously reviewed compiler, architecture,
   batching, or compatibility-certificate code is modified.
2. **Independent empirical cross-check against trusted ground truth** (the
   determining check for this review). Wrote a from-scratch script that
   builds the already-reviewed full symbolic PPM/frame trace
   (`lower_oop_qcla_to_symbolic_direct_ccz_ppm` /
   `lower_qcla_to_symbolic_direct_ccz_ppm`, extensively matrix-verified in
   `RV-20260901-005`/`RV-20260901-008`) as ground truth, then independently
   compared — with hand-written comparison code, not the reviewed
   `compare_support_certificate_to_symbolic_trace` function — every PPM's
   support-certificate `activities` (logical value + exact ANF monomials)
   against the compiler's `presented_observable.z_components` /
   `x_components`. This ran over all 60/120/114/228 = 522 PPMs at widths 5
   and 8 for both variants, with **zero mismatches**, correctly identifying
   29/197/89/634 branch-dependent component instances respectively. Since the
   compiler's presented-observable computation was independently verified at
   the primitive-gate level in earlier reviews, this is strong evidence the
   NEW sparse support-propagation algorithm computes the mathematically
   correct answer, independent of whatever internal representation
   (`_column_xor`/`_left_cnot`/the ZDD arena) it uses internally.
3. **Falsification witness verified directly**, not merely trusted from the
   contract prose: called `certify_qcla_direct_ccz_ppm_support` on a freshly
   built OOP width-5 trace and inspected `branch_dependence_witness` directly
   — confirmed `operation_id="direct-ccz:000005:ppm:zz_0"`,
   `logical_value="a:0"`, `anf_monomials=(("direct-ccz:000000:outcome:zz_1",),)`,
   with correct zero/one assignments — exactly matching the claim, and this
   specific PPM's support was also part of the 522-PPM ground-truth match in
   finding 2 above.
4. **May-support soundness for large IP widths**, verified by code reading
   rather than exhaustive testing (a genuine over-approximation is
   structurally guaranteed, not just empirically observed): every update to
   the `may` sets in `_sampled_source_cnot_conjugate` and
   `_sampled_conditional_column_xor` is a set `.update()` (monotonic union,
   never a removal), so `may[w]` can only grow across the whole propagation —
   this makes it a sound upper envelope by construction, independent of the
   specific hash-derived sample masks. The 512 concrete branch evaluations
   are a separate, independently-computed lower witness (each one an actual
   deterministic assignment of every outcome variable), and the code never
   promotes an unwitnessed `may` coordinate to a claimed possibility, exactly
   as the contract states.
5. **Width-256 internal consistency**, checked directly against
   `experiments/runs/T-20260903-002/summary.json`: witnessed-union
   (935) ≤ may-support upper bound (1,006); single-sampled-branch maximum
   (509) ≤ witnessed-union (935, since a union across branches must be at
   least as large as any one branch); witnessed contact (523) ≤ upper
   contact bound (567) — all the ordering relations the model requires hold.
6. **Fail-closed behavior.** Read
   `test_noncanonical_correction_map_fails_closed` and confirmed the
   certifier rejects a correction-frame reordering with
   `support_envelope_evidence_status=FALSIFIED`,
   `validation_counterexample.obligation="canonical_support_changing_correction_map"`,
   and empty profiles/null candidate count — it does not silently accept a
   non-canonical frame and compute wrong support.
7. **Tests, lint, types, reproducibility.** Reran
   `tests/unit/test_direct_ccz_ppm_support_certificate.py` (9 passed, ~184s)
   and the full suite (332 passed, the same two known unrelated sibling-pin

8. **Coordination records.** Read the `A-0040`, `D-0025` entries and all four
