  presented observable is `F P F^dagger`. The macro sequence
  `F_in -> F_in H_T -> append diagonal D -> H_T` equals the approved compiler's
  `F_in (H D H)` (pre-H `CZ` on the target becomes `CNOT`, target `Z` becomes `X`), and the
  six-bit correction structure matches the approved event map exactly.
- Independent recomputation with Stim 1.16 Clifford tableaus (prepend = right
  multiplication; own macro-plan pair oracle; own SHAKE bit extraction) for OOP and IP at
  width 256, branches -2, -1, 0, 17, 63 (10 traces): every macro's PPMs (`x`, `z`, phase =
  signed Hermitian Pauli, resource `Z` included) and all 1,008 X and 1,008 Z images of the
  retained final frame are **equal** to the stored artifacts. Macro counts 15/30, PPM counts
  3,687/7,374; (3,687 + 7,374) x 66 = 730,026 reproduces the reported coupling-PPM total.
- Multi-event macro semantics (new evidence; Codex's dense test covers one event): a

  a shared-control and a shared-target macro. The negative control (target of one event is

### F4. Non-blocking notes

   cites versioned HTML only. Please add both PDFs to the pinned corpus (I verified the cited
   content myself, so no claim changes).

   order of the PPMs entering `regularize` (another valid regularization) leaves the general
   surgery step counts unchanged (OOP K=64 116/116, unlimited 47/47; IP 259/259, 102/102 on

   contract already says ("not weight-optimized"); please state the observed roughly 10%
   sensitivity next to those counts.

   measures t logical Paulis in O(1) logical rounds with ancilla overhead O(t w polylog),
   w being the representative weight; here K caps simultaneous PPMs and `weight` is logical
   weight. The contract labels them `CHECK`; keep that wording when quoting (no paper result
   is reproduced).
4. **Reproducibility scope.** The implementer regenerated 6 of 132 artifacts; I regenerated 4
   different ones (IP 17, IP 63, OOP 63, OOP 5): bytes and summary rows identical. The rest
   are verified by content (F1-F3), not by a second byte comparison.
