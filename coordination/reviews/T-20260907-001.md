## Scope

scheduler, independent replay, exact demand/liveness records, bounded support
envelopes, and fail-closed native-output boundary. This is a structural

## Claims requiring review

1. For the in-place source, positive-control CCX target-control conflicts plus
   any intervening X or CNOT source layer define the complete retained-order
   relation used by this task. The compact streaming recurrence agrees with
   all 3,019,653 decisions from the full pair oracle.
2. The selected coherent construction has exact model-relative depth 30
   macros/60 two-phase candidates, witnessed by a thirty-event critical path,
   versus the source-aligned 34/68 baseline.
3. Reordering preserves exact modulo-`2^n` addition and clean ancillas across
   all 87,376 width-2--8 input pairs. The reverse cleanup network remains
   coherent; no measurement-uncompute shortcut is used.
4. CCZ/PPM/H/CNOT and source-coordinate liveness counts are exact logical
   demands. Sampled support witnesses and monotone may-support bounds are
   clearly separated and are not native or simultaneous geometry.
5. Native cycles, runtime, physical qubits, routing, capacity, failure,
   reaction/decoder service, and factory/buffer service remain null.

## Known limitations disclosed by implementer

- Exactness is relative to the declared unlimited-capacity logical dependency
  model, not a QEC-native execution model.
- Twenty-nine of sixty support levels retain sampled-versus-may-support
  uncertainty; a witnessed union combines branch incidences and is not itself
  a simultaneous branch.
- Liveness is measured in source algorithmic-layer coordinates rather than
  the commutation-aware macro schedule.
- The circuit is in-place addition modulo `2^256`, not prime-field reduction,
  a controlled modular adder, point addition, or the full ECDLP workload.

## Findings

Every checklist item was independently verified from scratch, using scripts
that import neither the new IP scheduler
(`width256_ip_commutation_aware_qcla.py`) nor its shipped replay module --
only the already-reviewed `build_qcla_trace(256)` in-place source builder.

1. **X-as-barrier necessity (checklist item 1).** Verified algebraically,
   independent of any code: for `X` applied to a qubit `q` and
   `CCX(c0,c1;t)`, `X` on the *target* commutes with the CCX (since
   `NOT(t XOR k) = (NOT t) XOR k` for any `k`), but `X` on a *control* does
   **not** commute in general -- a direct hand calculation with
   `c0=0,c1=1,t=0` gives target value `1` under "X then CCX" but `0` under
   "CCX then X". This confirms the contract's claim that treating only CNOT
   (and not X) layers as barriers would be an unsound generalization of the
   OOP rule, since a source X gate can genuinely fail to commute through a
   CCX that uses the touched wire as a control.
2. **Complete pair oracle and streaming certificate (checklist item 2).**
   Wrote an independent O(n^2) script implementing the dependency rule
   directly (edge iff noncommuting target/control overlap, or at least one
   X-layer-or-CNOT-layer lies strictly between the two source layers) and a
   from-scratch longest-path DP over the real 2,458 IP CCX events. Result,
   computed in ~3 seconds: `n_ccx=2458`, `n_cnot=1019`, `n_x=510` (all match
   the claimed source counts), `C(n,2)=3,019,653`, `dependency_pairs=
   2,012,691`, `admitted_pairs=1,006,962`, `noncommuting_pairs=12,996`, and
   `macro_depth=30` -- an **exact match, to every integer**, of the
   generated `pair_oracle` fields and the reduction from the 34-macro/
   68-level source-aligned baseline to the selected 30-macro/60-level
   result. The **complete 30-element macro-layer size vector** also matched
   exactly:
   `[255,253,126,64,34,23,20,28,40,61,66,72,53,70,64,253,126,64,34,23,20,28,
   40,61,66,72,53,70,64,255]`.
3. **Small-width bridge (checklist items 2-3).** Independently recomputed the
   `(source macro depth, commutation-aware macro depth)` pairs for widths
   2-8 with the same from-scratch script and got
   `(2,2),(4,4),(6,6),(12,8),(12,8),(14,10),(14,10)` -- an exact match to
   the contract's bridge table and the generated `compact_bridge_widths_2_to_8`
   field.
4. **Exhaustive small-width arithmetic (checklist item 3).** Confirmed the

5. **Exact demand and source-coordinate liveness (checklist item 4).**
