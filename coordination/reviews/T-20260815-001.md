- Confirmed the measurement node can be released independently of the frame/correction node (`test_measurement_releases_temporary_without_waiting_for_frame_application`): the temporary's wire only appears in the measurement node's `wire_support`, and the correction only touches the control wires, so the DAG correctly does not force the temporary's release to wait on the correction, while a later operation on either control is still ordered after the correction via the per-wire chain.
- `CircuitDag._validate` is a real, exercised guard, not decoration: it separately checks node-ID/edge/classical-value/lifetime uniqueness, that every feed-forward-consuming node has a corresponding edge, that lifetimes don't end before their first use or get released before their last use (via `topological_order`), and that direct operands are a subset of processor occupancy. `test_adapter_rejects_unverified_or_wrong_mapping_input` confirms the schema/verification-status gate actually rejects malformed input rather than silently degrading.
- Evidence-status labeling (`NUMERICAL` for widths 2-4, `LITERATURE` for width 256) is derived from the oracle's own `phase_verification_provenance.method` field rather than hardcoded per width, so the label tracks what the external oracle actually claims about itself; this is an appropriate boundary given the adapter is documented as read-only and non-authoritative over the source's own verification claims.
- No code-block, syndrome-round, physical-qubit, decoder, routing, bridge, or Factory concept appears anywhere in `dag.py` or `gidney_adapter.py`; `critical_path_node_count`'s docstring and the contract doc both correctly disclaim it as a unit-weight semantic count, not a wall-clock or syndrome-round schedule, matching the required lower-bound/heuristic/realizable separation in `CONVENTIONS.md`.
- `context/RESULT_LEDGER.md` (`R-20260815-001`) and `context/DECISIONS.md` (`D-0003`, `D-0004`) were updated in the same submission with correct `NUMERICAL`/`PROVISIONAL` labels rather than being deferred or skipped, consistent with the completion procedure.
- Non-blocking observation: `_erase_nodes` gives the measurement node the *unfiltered* `unit.memory_support`/`unit.occupancy_support` (including the two control values it does not itself touch), while the frame node gets the same sets with only the measured value removed. This means both expanded nodes independently declare occupancy of the two control values. It does not break any current invariant or test (nothing yet sums `required_memory_values` across nodes into a load/store count), and can be read as intentionally conservative (the controls must stay resident across the whole erase gadget, not just the correction half). But `docs/GIDNEY_DAG_CONTRACT.md` doesn't currently say this, and a future memory-I/O model (`T-BOOT-005`) that sums per-node memory support rather than diffing residency transitions would double-count a load for every erase event. Recommend adding one sentence to the contract's "Temporary-AND erase expansion" section stating that both expanded nodes retain full control occupancy by design, so `T-BOOT-005` is written against a diff/replacement-policy model rather than a per-node sum.
