## Findings

Scientific -- primitive Clifford-conjugation math:

- Wrote a from-scratch numpy script (not importing anything from the
  reviewed module) that builds real Hermitian Pauli matrices for every
  (x,z) bit combination on 1-2 qubits and directly computes `U P U-dagger`
  for H, X, Z, and CNOT, then decomposes the result back into a signed
  Pauli. All 3 single-qubit cases each for H/X/Z and all 16 two-qubit CNOT
  cases matched `apply_gate`'s symbolic prediction exactly, including sign.
  The CNOT phase formula `xc*zt*(xt XOR zc XOR 1)` is the textbook
  Aaronson-Gottesman (2004) stabilizer-tracking sign-update rule for CNOT,
  which I recognized independently of reading the code.
- Independently verified the matrix identity `H_t . CNOT(c,t) . H_t ==
  CZ(c,t)` used to implement `apply_gate`'s CZ case, and then verified all
  16 CZ conjugation cases via the composite matrix directly -- confirming
  the CZ case is correctly built from the already-verified H/CNOT
  primitives rather than a separately hand-derived (and separately
  error-prone) formula.
- Algebraically re-derived, independent of the code, why
  `presented_under_correction_frame` must traverse `reversed(frame_terms)`
  to compute `C-dagger P C`: since every stored primitive is self-inverse,
  `C = term_n∘...∘term_1` (term_1 applied first physically) gives
  `C-dagger P C = term_1(term_2(...term_n(P)))`, i.e. innermost-to-outermost
  in REVERSE term order -- exactly what the code does. This directly
  confirms the "explicitly checking the `C† P C` direction" item from the
  review's own checklist, from first principles rather than by reading the
  docstring's claim.

Scientific -- end-to-end nontrivial case (the review's checklist item 1):

- Picked T8's first PPM (a later, non-degenerate case: its incoming frame
  had accumulated corrections from two earlier injections, T2 and T6, both
  touching the `b:1`/`z:2`/`a:1` wires) and tried to reconstruct its
  `presented_observable` independently. My first attempt (collecting
  `correction_updates` filtered to prior injections) reproduced 6 of 7
  affected logical-wire components exactly but mismatched on `a:1`. I hand
  algebra'd the T2+T6 interaction term by term and got the same wrong
  answer as my script -- both omitted something. The actual bug: a
  passthrough CNOT (`C1 = CNOT(a:1,b:1)`, source layer 2, between T2 and
  T6/T8 in circuit order) conjugates **every already-emitted frame term's
  stored circuit** (`U C U†`, the `_conjugate_frame_by_gate` step) as it
  executes -- my reconstruction had only replayed correction-term appends,
  not this circuit-conjugation step. Once I replayed the full interleaved
  history (append correction terms on CCX gates, conjugate all existing
  terms on passthrough CNOTs) via `trace.source_operations` in true
  circuit order, and called the actual imported
  `presented_under_correction_frame` on the correctly-replayed 42-term
  frame, the reconstruction matched the compiler's stored value exactly,
  component for component, sign included. This was a genuine bug in my own
  verification script, not in the reviewed code -- caught and fixed
  in-session rather than reported as a false defect. It also directly and
  rigorously exercises the "pass-through CNOT ... updates the frame as
  `U C U†`" claim (checklist item 2/3), since the mismatch would not have
  resolved unless that rule were implemented correctly on both sides.
