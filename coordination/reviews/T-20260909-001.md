## Scope

Review the convention-explicit target-component partial Clifford-frame
clearing policy for the already-reviewed coherent in-place QCLA 30/60 logical
workload.  The task proves an ordered component factorization, anchors it with
width-5 exact symbolic checks, and profiles width 256.  It does not claim a
minimum Clifford synthesis, native surgery schedule, or runtime.

## Claims requiring review

1. Under `physical = F ideal`, the implementation equation is
   `G = F_out U F_in^dagger`.
2. The stable interaction-component partition gives exact `F_in = A R`, with
   disjoint support and `[R,U_H]=0`; therefore applying `G = U_H A^dagger`
   leaves `F_out = R`.
3. Width 5 checks factorization, physical action, and commutation on every
   logical X/Z generator for 16 branches and eight macro layers: 11,520 checks
   with zero mismatch.
4. On 32 fixed width-256 witnesses, partial clearing has median 3,843 literal
   CNOTs versus 4,250 for full clearing, but median CNOT-batch/logical-layer
   envelopes 284/380 versus 176/270.  Its presented PPM weight is median 11,
   sampled maximum 16, and remains in the sampled Z/X-only family.
5. Literal generator counts and ASAP envelopes are not minimal synthesis or
   native cost; all native cycle, runtime, physical-qubit, and failure fields
   remain null.

## Findings (claude, 2026-09-26)

Method: every check below was done with code that does **not** import
`qcla_partial_frame_clearing` (analysis or verification). Only the already-approved
source-trace builder, direct-CCZ event lowering and (for one check) the approved
symbolic compiler were used as inputs/oracles. Scripts are in the reviewer scratch
space, not the repository.

### F1. Convention and factor order: confirmed

- Read the approved compiler (`direct_ccz_ppm.py`): correction terms are stored as
  `C` in circuit order (`physical = C^dagger logical`), new-event terms are appended
  (`C_new C_in`), a source gate conjugates every term as `g t g`, and the presented
  observable is `C^dagger P C`. With `F = C^dagger`, the frame list read left to
  right is the mathematical word `f1 f2 ... fm`, so appending event terms and
  `(*layer, *frame, *reversed(layer))` are the correct updates. The identical
  list is the chronological `C`. `_tableau` composes on the right
  (`T' = T g`), i.e. it computes `F P F^dagger`, which is the compiler's presented
  observable.
- `G = F_out U F_in^dagger` gives, for every policy, the circuits the code builds:
  full conjugation `A U A^dagger` (residual `R` commutes with `U`), full clearing
  `U F_in^dagger` with `F_out = I`, partial `U A^dagger` with `F_out = R`, bare
  `F_out = U F U^dagger`, tracked `F_out = F U^dagger`. Because corrections are
  appended only after the closing H, opening+closing H cancel and the frame
  entering the next macro equals `F_in` for bare/tracked as well, so reusing the
  full-conjugation frame history for those two rows is correct (not an artifact).
- `_compile_corrections` reproduces the compiler's `_end_of_injection_correction_terms`
  exactly (pre-H `CZ` touching the H target becomes `CNOT(control,target)`).
- The width-5 exact check is meaningful for the algebra: dropping the reversal of
  `A^dagger` produces mismatches (2 of 8 generator images in a 4-qubit test).

### F2. Frame accumulation validated against the approved compiler (new evidence)

The 11,520 width-5 checks verify algebraic identities *for the frame the
implementation already holds*; they do not test how that frame was accumulated.
So I patched the macro grouping to source layers (which the approved compiler
implements) and compared, for all 16 branches x 12 layer groups = 192 rows, the
maximum presented phase-one PPM support and the count of non-Z axes against the
approved `lower_qcla_to_symbolic_direct_ccz_ppm` output evaluated on the same
branch assignments: **192/192 agree** (weights range 2..10, so the test is not
trivial). A deliberately wrong order (prepending instead of appending event
corrections) is detected in 66 of 192 rows.

### F3. Width-5 and width-256 vectors reproduced by a second implementation

I wrote a second implementation from scratch (chronological `C` list, own
union-find, own ASAP, own condition evaluator from the event strings, own
SHAKE-256 branch masks, own complete O(n^2) pair oracle for macro layers,
forward `C^dagger P C` push-back for PPM weights).

- Width 5 (16 branches): after adopting the same intra-layer generator order and
  time direction, all nine vectors for full conjugation, full clearing and partial
  clearing (literal CNOT, CNOT batches, layer envelope) are equal branch by branch.
- Width 256 (32 branches): macro depth 30 with sizes 255, 253, 126, 64, ...
  (matches the reviewed schedule). Reproduced exactly:

  | quantity | full clearing | partial clearing | full conjugation |
  |---|---|---|---|
  | literal CNOT p50 / max | 4,250 / 6,444 | 3,843 / 6,052 | 253,684 / 400,248 |
  | CNOT batches p50 / max | 176 / 249 | 284 / 406 | 4,052 / 6,030 |
  | logical layers p50 | 270 | 380 | 4,114 |
  | final frame p50 / max | 1,273 / 1,318 | 1,862 / 1,967 | 10,436 / 10,535 |
  | presented PPM weight p50 / max | 2 / 2 (identity frame) | 11 / 16 | not recomputed (see below) |

  The partial-vs-full-clearing CNOT saving 9.58% (3,843 vs 4,250) is reproduced.
  Full-conjugation PPM weight 134/509 was not recomputed (a Python push-back
  through a 10k-gate frame was impractical); it is consistent with the reviewed
  `RV-20260907-002` all-one boundary maximum 509 and with F2 at width 5.

### F4. Non-blocking: literal and batch numbers are representation-dependent

Both differences below were found while making the second implementation agree
with the first, and are properties of the metric, not bugs.

1. **CNOT-batch envelope depends on ASAP time direction.** The stored frame list is
   a mathematical-order word (i.e. time-reversed), and `_asap_metrics` schedules it
   as if it were chronological. Depth is direction-invariant, but "number of
   layers containing a CNOT" is not. Scheduling the true chronological circuit
   (`C` then `U`) forward gives width-256 CNOT batches 148 (full clearing) and 249
   (partial) instead of 176/284, and layer envelope 270/379 instead of 270/380.
   The qualitative conclusion (partial has fewer CNOT occurrences but more
   serialized batches/layers than full clearing) is unchanged; the ratio moves
   from 1.61 to 1.68.
2. **Literal CNOT count depends on generator order inside a source layer.** Layer
   gates are disjoint and commute, but `norm` cancels only syntactically adjacent
   generators. Sequential per-gate conjugation vs
   `(*layer, *frame, *reversed(layer))` changes one width-5 branch from 44 to 42
   CNOTs. At width-256 medians the counts were identical in both orderings.

Requested (documentation only, may be done at the next task that touches the
contract): state that the CNOT-batch envelope is an ASAP number on the stored
(reverse-chronological) word, and that literal counts are order-dependent to about
one CNOT per affected layer; keep the layer envelope as the primary depth number.

### F5. Non-blocking: replay independence is weaker than the checklist item wants

- The independent verifier re-derives the macro layers and re-checks stored
  quantiles/hashes/ordering guards, but it does not recompute any frame quantity;
  `expected_checks = branches * macros * 3 * 2 * logicals` is a count identity
  derived from the same loop shape, so it cannot fail independently of the
  generator. The implementer disclosed this. F2/F3 above close the gap for this
  review; I recommend adding F2 (compiler cross-check at width 5, ~20 lines) as a
  regression test in a later task.
- The ordered-factorization claim is correctly `PROVED` (disjoint-support
  components commute; `[R,U_H]=0` because `R` avoids every H target, which
  `_split_target_components` enforces with two explicit guards: no shared support
  between `A` and `R`, and no `R` support on an H target). Z-only presentation of
  the retained frame (`incompatible = 0`) is a consequence of the
  `X/Z/CNOT/CZ` closure already approved in `RV-20260903-001`, not new evidence.
